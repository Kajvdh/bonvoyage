An open protocol for ticket printers

Send a ticket to a friend's printer.

Bonvoyage lets ticket printers in different homes send each other notes, lists and silly drawings. Nothing at home is exposed to the internet, and the relay in the middle can't read a word.

How it works

A sealed note, a mailbox, and two printers.

Both printers only ever connect outward, to a relay. The relay is a mailbox that holds sealed tickets until the recipient collects them.

SenderYour printer

Signs the ticket with its own key, then seals it for the recipient.

→drops
In betweenThe relay

Stores unreadable bytes. Never learns the content or who sent it.

←collects
RecipientTheir printer

Opens it, checks the signature and its own rules, then prints.

  1. Pair

    Hand someone a contact card, ideally as a QR code printed on a ticket. Whoever uses it first becomes that contact, so it is valid for a week and you can take it back.

  2. Seal and drop

    The sender builds a ticket from simple blocks, signs it, seals it for you and drops it in your inbox on the relay.

  3. Collect and print

    Your printer picks it up on its next round, verifies who it is from, applies your limits and quiet hours, and prints.

Quick start

Try it in two minutes, no printer needed.

The project ships a small reference client that prints tickets as text in your terminal. Play both sides yourself to see a ticket travel through this relay.

What you need

Python 3.10 or newer, and git. The only library is PyNaCl, which provides the signing and sealing.

What happens

  • Two identities are created, each with its own inbox on the relay.
  • "Jan" issues a contact card for "Kaj": one line starting with bonvoyage://.
  • "Kaj" uses that card to send a signed, sealed ticket.
  • "Jan" collects it, checks who it is from, and shows it.

With a friend it works the same: each of you runs init once, then you swap cards.

git clone https://github.com/Kajvdh/bonvoyage
cd bonvoyage
pip install pynacl

# two printers (play both to try it)
python examples/bonvoyage.py init kaj.json \
    --relay bonvoyage.kaj.dev --name Kaj
python examples/bonvoyage.py init jan.json \
    --relay bonvoyage.kaj.dev --name Jan

# Jan makes a contact card for Kaj
python examples/bonvoyage.py card jan.json Kaj
#  -> bonvoyage://...    copy that line

# Kaj sends Jan a ticket with it
python examples/bonvoyage.py send kaj.json \
    'bonvoyage://...' 'Welcome to the club!'

# Jan collects
python examples/bonvoyage.py receive jan.json
#  -> --- from Kaj ---
#     Welcome to the club!

Principles

Paper comes out in someone's home. That sets the rules.

🔒

Private by design

Tickets are signed and sealed end to end. The relay stores bytes it cannot open, and it cannot make your printer print something a contact did not send.

🏠

Nothing exposed at home

No open ports, no tunnels, no public address for your printer. It makes ordinary outgoing HTTPS requests and nothing else.

✋

The recipient decides

Strangers are dropped. Daily limits, quiet hours and approve-before-print are yours to set, and they always win.

🔧

Open to any printer

The protocol is a short spec with test vectors. It is not tied to any software, printer brand or relay; addresses name their relay, like email.

Privacy, stated plainly

What a relay can and cannot know.

No relay can be blind to everything. This is the complete list, so you can decide whether to use this one or run your own.

It can never learn

  • what a ticket says or shows
  • the sender's name or address (they travel inside the sealed part)
  • the names of your contacts
  • how long a ticket really is (tickets are padded to fixed sizes)

It does see

  • that an inbox received something, and when
  • the padded size of each sealed ticket
  • how many contacts you have, and how often each one writes (each contact has their own pass for your inbox; the relay sees which pass was used, not whose it is)
  • the IP address of whoever connects (this relay keeps no request logs)

One thing follows from that last line. If you and a contact use the same relay, it sees the same IP address collect from one inbox and drop into another, and could work out that you two write to each other. It still cannot read anything. If that matters to you, use a different relay from your contacts, or run your own.

Build a client

Connect your own printer.

A client is the piece of software between the relay and your printer. You write it once, in any language, for whatever printer setup you have.

Path 1

Let an AI assistant write it

The spec and test vectors are written to be handed to a coding assistant. Give it both files and a prompt like this:

Implement a Bonvoyage client in <language> following SPEC.md. Prove it is correct by passing every case in vectors/v1.json, including must_reject. Then connect it to my printer at <address>.
Path 2

Write it yourself

Read the spec (one document), keep the reference client open next to it, and check your work against the test vectors as you go.

The cryptography is two functions from libsodium, which exists for every common language: Ed25519 signatures and sealed boxes.

What are test vectors?

Worked examples with the answers filled in. The file says: with exactly these keys and this ticket, the signature is exactly this, and this sealed message opens to exactly that.

Your code runs the same inputs. If every answer matches, it speaks the protocol correctly, and you know that before involving a second person or a relay.

They also cover what must fail. The file contains messages that are expired, addressed to someone else, or tampered with. A correct client refuses every one.

What a ticket looks like

Content, never printer commands. Every recipient renders it in its own style, for its own paper width.

{ "blocks": [
  { "type": "text", "text": "Dag Jan!",

  { "type": "list", "style": "check",
    "items": ["koffie", "taart"] },

Rather run your own?

The relay is one small codebase that runs on the free plan of Cloudflare Workers or on any server with Node. People on different relays can still exchange tickets.

A set of conformance tests checks any relay, yours or this one, against the spec.

# on your own server
node src/server.js

# or on Cloudflare Workers
npx wrangler deploy

# check any relay against the spec
RELAY_URL=https://relay.example npm test
